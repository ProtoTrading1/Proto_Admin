## 12:12 SAST — Replace the unsubscribe tag design with the real opt-out page

- Summary: The `{{unsubscribe}}` design restored this morning (from `9e5a20c`)
  was the wrong one for this codebase and produced the Brevo 404 Daniel hit.
  Two faults: the tag expanded to a whole `<a>` anchor, so writing the natural
  `href="{{unsubscribe}}"` nested an anchor inside an href attribute; and its
  destination defaulted to a `mailto:`, which Brevo's click tracker rewrites to
  a `sendibt3.com` URL that cannot resolve. The result was a SendinBlue "Page
  not found" instead of an unsubscribe. Reverted it (`53fff58`) and cherry-picked
  the PR #228 design instead: `{{unsubscribe}}` and `{{unsubscribe_url}}` are
  ordinary merge vars resolving to a signed HTTPS URL, so they work inside an
  href, and they point at `api/email-unsubscribe.js` — a real page reading "You
  have been unsubscribed", which records the opt-out and is then honoured by
  every later broadcast.
- Files affected: `api/_brevo-email.js`, `api/email-unsubscribe.js` (new),
  `api/customer-email-broadcast.js`, `src/lib/emailMergeTags.js`,
  `src/lib/protoUrls.js`, `src/components/CustomerEmailModal.jsx`,
  `migrations/064_marketing_email_opt_outs.sql`, and
  `tests/email-unsubscribe-flow.test.js`.
- Systems affected: Admin email composer, the Brevo broadcast send path, and a
  new public unauthenticated GET/POST endpoint at `/api/email-unsubscribe`.
  Links are HMAC-signed; an unsigned or altered link is refused.
- Database: migration `064_marketing_email_opt_outs.sql` is included in the repo
  but was NOT applied by this work — `public.marketing_email_opt_outs` already
  exists in production, applied when this branch was live in prod on 2026-08-20.
  Verified by querying `information_schema.tables`. No schema change was made.
- Environment: no new variables required. `MARKETING_UNSUBSCRIBE_SECRET` falls
  back to `SUPABASE_SERVICE_ROLE_KEY`, and the old `UNSUBSCRIBE_URL` /
  `VITE_UNSUBSCRIBE_URL` are now unused.
- Verification: Email suites 47/47; lint and production build pass. Full suite
  747/748 — the single failure is the unrelated pre-existing Image Processing
  Centre queue-refresh regression.
